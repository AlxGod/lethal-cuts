# Lethal Cuts

A Windows program for Magic Commander game recordings: iPhone .mov (HEVC) from in-person games, or OBS recordings of Tabletop Simulator games. It makes vertical 9:16 clips for YouTube Shorts and TikTok, and long widescreen videos with the dead stretches cut out. The full feature plan is the Google Doc "Lethal Cuts – Build Plan". It is built in steps, each tested and signed off before the next. Version 0.4.1 has Phase 1 (the core clipper), the Post tab, long videos, the Record tab, a chosen save folder, the Update button, and help for 3-hour games (moment key, timeline zoom, free-space check, upload-length warnings). Phase 2 (clicker and "clip that" markers, captions, card pop-ups, hook text) and Phase 3 (reaction cam) come once the friend has used it on real games. `README.txt` is the plain-English guide for the friend. The code is on GitHub (public, because the Update button downloads from its Releases): https://github.com/AlxGod/lethal-cuts

## How it's organized

- `lethal_cuts/app.py`: starts the program and sets the dark theme. Run with `python -m lethal_cuts [video]`, or double-click `Run Lethal Cuts.bat`.
- `lethal_cuts/main_window.py`: the main window. Tabs: Record, Editor, Post, Guide, Settings (compare tabs by widget, e.g. `self.editor_page`, never by index). It holds the player, controls, hotkeys, marking, fine-tune (nudge), crop and preview, export, tips, the walkthrough, autosave and the update bar. The Editor has a Shorts / Long video switch (`set_mode`). `items()` and `active_list()` return the clips or the cuts for the current mode, and most editing code goes through them.
- `lethal_cuts/selfcheck.py`: `python -m lethal_cuts --check [log] [--quiet]` (or `Lethal Cuts.exe --check`) makes a test HEVC video, plays it in the built-in player, exports a clip, and writes what it found to a text file.
- `lethal_cuts/project.py`: the `Clip` and `Project` data. Each video `game.mov` gets `game.lcproj` (JSON) next to it, with the Shorts `clips` and the long video's `cuts` (both `Clip`), written through a temporary file so a crash can't corrupt it.
- `lethal_cuts/timeline.py`: the custom-drawn timeline (bars, start mark, playhead, click to seek). With `cut_style` on, the bars are drawn as striped red cuts. Moments are gold flags with the minutes before them shaded. The wheel zooms (down to 20 s) around the cursor, Shift+wheel slides, double-click zooms out; `view()` is (start, length), `view_changed` drives the main window's scroll bar, and a moving playhead pages the view along.
- `lethal_cuts/hotkey.py`: `GlobalHotkey`, Windows RegisterHotKey on its own thread with a GetMessage loop (works with the game in front, and Windows doesn't pass the key on to the game). Only held while recording. Tests press F13 with keybd_event, which no program uses.
- `lethal_cuts/limits.py`: upload limits (Shorts 3 min, YouTube 15 min until phone-verified, TikTok 60 min) and `LimitNote`, the gold note with Verify / "It's verified, stop telling me" buttons used in the Editor (long mode) and the Post tab. The Post tab also turns off the TikTok button for videos over 60 minutes.
- `lethal_cuts/clip_list.py` and `cut_list.py`: the side tables of clips (preview, number, editable name, start, length) and of cuts.
- `lethal_cuts/thumbnails.py`: the preview pictures, made by FFmpeg on background threads. Requests are bunched up with a short timer, and stale ones are dropped, so holding a nudge button doesn't queue hundreds of FFmpeg runs.
- `lethal_cuts/export.py`: the Shorts export engine (no UI). `probe()` reads size (swapped for rotated phone video), frame rate, audio and HDR. The video goes through crop, lanczos scale to 1080x1920, tone-mapping HLG/PQ to SDR (zscale+tonemap) if needed, a bt709 `setparams` tag, `fps=` for constant frame rate, then libx264 CRF 19. h264_nvenc is used instead if a tiny test encode works, falling back to the CPU mid-batch if it fails. Audio uses two-pass loudnorm (-14 LUFS, -1.5 dBTP, linear) to 48 kHz AAC. Progress comes from `-progress pipe:1`.
- `lethal_cuts/long_export.py`: the long video engine. One FFmpeg pass with `select`/`aselect` keeps everything outside the cuts, so it needs no extra memory or temp files. Cuts snap to frame boundaries, and the sound goes through `asetnsamples` in chunks exactly one frame long (48000/fps samples) before `aselect`, so picture and sound lose the same time and can't drift apart. Tested with 60 cuts: both came out the same length to the millisecond. Size is 1080p or the source size (Settings), and loudness is two-pass over the whole kept audio. `LongExportWorker` has the same signals as `ExportWorker`.
- `lethal_cuts/export_dialog.py`: the export window, for either worker (`worker=` and `title=` for long videos). `ExportWorker` runs on a QThread, writes `NN name.partial.mp4` and renames it when done, so cancelled or failed clips leave nothing behind. "See them in the Post tab" closes it and switches tabs.
- `lethal_cuts/folders.py`: one save folder (`settings.save_folder`, filled in on the first start from `program\install.ini`, which the installer writes; otherwise Videos\Lethal Cuts). It has `Recordings`, `Shorts\<game>` and `Long videos` folders. `is_inside_program()` refuses a save folder inside the program's own folder (updates wipe that).
- `lethal_cuts/library.py`: every exported Short and long video (`kind`) from every game, and where each was posted, in `library.json` beside settings.json. The main window adds the finished files after the export window closes. Re-exporting the same file keeps its posted marks; files deleted by hand drop off the list.
- `lethal_cuts/post_page.py`: the Post tab. A New/Posted list of preview pictures (FFmpeg, reusing `thumbnails._Job`), a phone-shaped player (QGraphicsVideoItem, like the Editor; a QVideoWidget can't be screenshotted in tests), "Post to YouTube/TikTok" (opens the upload page, highlights the file in Explorer, copies the name), "Posted on ..." ticks, Show in folder, Delete (Recycle Bin), and the "Saved in" bar. The player must let go of the file (`setSource(QUrl())`) before a delete, or Windows refuses.
- `lethal_cuts/obs.py` and `record_page.py`: recording with OBS, copied from Clip Drop's method. Lethal Cuts writes its own "Lethal Cuts" OBS profile (Simple output, hybrid MP4, 1080p30, NVENC if `nvEncodeAPI64.dll` exists, else x264) and scene collection (game capture of the Tabletop Simulator window fitted to the canvas, Desktop Audio for game + Discord, default mic). It writes them only if missing, and afterwards only updates the recordings folder, so changes made in OBS stick. It sets `ConfirmOnExit=false`, plus `FirstRun=true` if missing so a new OBS skips its wizard. Then it starts OBS with `--profile/--collection "Lethal Cuts" --startrecording --minimize-to-tray`, and stops it with WM_CLOSE to its main window. Never kill OBS (that triggers a safe-mode prompt). `LETHALCUTS_OBS_CONFIG` points at a scratch OBS settings folder for tests. Tested for real on Alex's OBS 32.1 on 2026-10-17: it starts in about 12 s and closes in 2 s. While recording, the moment key (F8 by default) stores time.time() presses; on stop they're turned into seconds from the recording file's creation time (`st_ctime`) and saved as `moments` in that video's .lcproj. The Record tab shows free space in hours (8 GB/hour guessed until a recording over 5 minutes teaches `record_gb_per_hour`), asks before starting with less than 3 hours of room, and warns under 3 GB.
- `lethal_cuts/updater.py`: once per start, the installed (frozen) program asks the GitHub API for `releases/latest` of AlxGod/lethal-cuts. If the tag is newer, a gold bar offers Update now. That downloads the Setup .exe asset to `%TEMP%\Lethal Cuts update`, runs it with `/SILENT /SUPPRESSMSGBOXES /NOCANCEL /RESTART` and quits; the installer reopens the program. Help > Check for updates checks by hand.
- `lethal_cuts/settings.py`: the `Settings` dataclass (hotkeys, padding, jump size, save folder, quality, long video size, tips, colors, OBS path, open-after-record, moment key and minutes, learned recording size, youtube_verified, editor_volume (Editor playback only, applied squared), walkthrough_done). Saved as JSON in `%APPDATA%\Lethal Cuts\settings.json`, which survives reinstalls. `LETHALCUTS_DATA` points it at another folder: always set it in tests, so real AppData is never touched. A damaged file or bad values fall back to the defaults.
- `lethal_cuts/settings_page.py`, `guide.py`, `help.py`, `walkthrough.py`: the Settings tab (saves on every change), the Guide tab (HTML in a QTextBrowser, rebuilt so it shows the current hotkeys), the "?" buttons (`HELP` texts, shown with QWhatsThis; some are swapped per mode via `help_text`), and the first-run walkthrough.
- Hotkeys are QShortcuts rebuilt by `MainWindow.apply_settings()`. They only fire on the Editor tab and not while the walkthrough is showing.
- `lethal_cuts/tools.py`: finds FFmpeg (bundled `vendor/ffmpeg/ffmpeg.exe` first, then PATH) and runs it without a console window.
- `lethal_cuts/video_view.py` and `crop.py`: the video in a QGraphicsView with the 9:16 crop box (Shorts mode only), and the crop maths (a `Crop` is fractions x, y, h of the picture).

## Choices made

- Video playback uses Qt's own player (QMediaPlayer with Qt's bundled FFmpeg backend), not libmpv: it plays 4K 10-bit HEVC at full speed and 4x, with nothing extra to install.
- Exports even out loudness automatically (Alex asked for this).
- Long videos are made by marking what to cut (not what to keep), because most of a game stays in. Recording uses OBS rather than a built-in recorder, like Clip Drop: OBS records the game window and the computer's sound well and barely slows the game.
- On Alex's PC (GTX 1080 Ti), FFmpeg's NVENC fails with this build, so exports use the CPU (about 1.3 s per second of busy 4K). OBS's own NVENC does work there. The friend's RTX 5070 should use NVENC for both.

## Qt player gotchas

- `QGraphicsVideoItem.nativeSize()` stays empty with the FFmpeg backend. Use `video_item.videoSink().videoSize()`, and its `videoSizeChanged` signal.
- `boundingRect()` is the whole item, not the letterboxed picture. `VideoView.video_rect()` works out the real picture area.
- A stopped player draws nothing when seeking, so pause it once a video loads. Calling `pause()` inside the `mediaStatusChanged` handler crashes Python (segfault), so it's deferred with `QTimer.singleShot(0, ...)`.

## Testing

Test offline with a small generated clip in a temp folder, never in this folder. For example:
`ffmpeg -f lavfi -i testsrc2=size=3840x2160:rate=30:duration=20 -f lavfi -i sine=frequency=330:duration=20 -vf "select='not(eq(mod(n,10),3))',format=yuv420p10le" -fps_mode vfr -c:v libx265 -preset ultrafast -tag:v hvc1 -c:a aac test.mov`
(dropping every 10th frame makes it variable frame rate like an iPhone).
- Drive the window with `QTest` and save `window.grab()` screenshots.
- Fake anything that would leave the test: QDesktopServices.openUrl, post_page.show_in_folder, post_page.QFile for the Recycle Bin, QMessageBox.question, `updater._get` for GitHub, and the `obs` functions.
- Turn tips off in the test settings (`"nudges": false`), or the "Before you export" box waits forever for a click.
- Run tests with a time limit (`timeout 300 python -u test.py > out.txt`).
- When patching files with a script from the Bash tool, write the script to a file first. Inline heredocs turned `\n` in Python strings into real line breaks.

## Building and releasing

Run `python packaging/build.py`, or double-click `Build installer.bat`. It needs PySide6, PyInstaller and Inno Setup 6 (`winget install JRSoftware.InnoSetup --scope user`).
- FFmpeg 9.0 "gpl-shared" (from BtbN on GitHub, about 85 MB) downloads once into `%TEMP%\pyi-build\LethalCuts\ffmpeg`. PyInstaller leftovers also go under `%TEMP%\pyi-build\LethalCuts`, never in this folder. The GPL build is needed because LGPL builds have no libx264.
- PyInstaller makes a one-folder program with `--contents-directory .`, so `vendor\ffmpeg` sits beside `Lethal Cuts.exe`. FFmpeg is copied in after PyInstaller runs; given to PyInstaller, it would follow ffmpeg.exe's DLLs and put a second 180 MB copy beside the exe.
- `packaging/installer.iss` (Inno Setup) installs per user (no admin). It asks for the install folder (default `%LOCALAPPDATA%\Programs\Lethal Cuts`) and the save folder (written to `program\install.ini`; `/SAVEDIR=<folder>` sets it silently). The program goes in `<install folder>\program`, and only that is wiped on updates (`[InstallDelete]`), so videos saved anywhere else, even in the install folder, are safe. The install folder gets "Lethal Cuts" and "Uninstall Lethal Cuts" shortcuts. Updates reuse the first install's folders without asking. `/RESTART` reopens the program after a silent install (used by the Update button).
- Output: `dist\Lethal Cuts Setup <version>.exe` and `dist\Lethal Cuts <version>.zip` (installer + README + source). `dist` is git-ignored.
- To release a new version: bump `__version__` in `lethal_cuts/__init__.py`, commit, `git push`, run the build, then `gh release create v<version> "dist/Lethal Cuts Setup <version>.exe" --title "Lethal Cuts <version>" --notes "<plain-English changes>"`. Every installed copy then offers the update the next time it opens.
- To test an install without touching the real desktop or Start menu: `"Lethal Cuts Setup <version>.exe" /VERYSILENT /SUPPRESSMSGBOXES /NOICONS /MERGETASKS=!desktopicon /DIR=<scratch> /SAVEDIR=<scratch>\videos`, then `<scratch>\program\Lethal Cuts.exe --check <log> --quiet`, then `<scratch>\program\unins000.exe /VERYSILENT`. From Git Bash, run the installer directly, not through `cmd /c` (the quoting breaks), and run ISCC from Python (Git Bash mangles its `/D` options).
- The icon is drawn by `packaging/make_icon.py` into `assets/icon.ico` and `assets/icon-512.png`.
- The installer isn't code-signed, so Windows SmartScreen warns on first run ("More info" > "Run anyway"). The README explains this.
